# 모두찾아줘

<img src="assets/modufind.png" alt="모두찾아줘 아이콘" width="96" height="96">

**파일 이름이 기억나지 않아도, 문서에 들어 있던 단어로 찾으세요.**

파일명·폴더 경로·엑셀 시트명·문서 본문을 함께 검색하고 문서 형식을 변환하는 Windows 프로그램입니다. 문서 변환은 [KnifeLemon/Filee](https://github.com/KnifeLemon/Filee)의 공식 2.4.1 CLI와 같은 엔진을 사용합니다. 내 PC 문서 검색과 변환은 PC 안에서 처리합니다.

**1.3.0:** kordoc 구조 파싱, 자연어 원문 근거 답변, 법령·학교·통계·기업지원·공시 조회, 로컬 Ollama 요약, 북마크·태그·문서 비교·변경 자동 반영을 추가했습니다. 사용법과 연결·인증키 안내는 [자연어 근거 검색 안내](RESEARCH.md)를 참고하세요.

[최신 설치 파일 받기](https://github.com/Reensdogood/modu-find/releases/latest) · [문제 신고](https://github.com/Reensdogood/modu-find/issues)

## 설치

1. 최신 릴리스에서 `ModuFind-Setup-버전-win-x64.exe`를 받습니다.
2. 설치 프로그램을 실행합니다. 현재 Windows 계정에 설치하므로 관리자 권한은 필요하지 않습니다.
3. 바탕화면 또는 시작 메뉴의 **모두찾아줘**를 실행합니다.

Windows 10/11의 64비트 환경용입니다. .NET·Python·Excel·한글을 별도로 설치하지 않아도 검색할 수 있습니다. 원본 파일을 여는 데는 해당 형식을 지원하는 프로그램이 필요할 수 있습니다.

설치 위치는 `%LOCALAPPDATA%\Programs\ModuFind`입니다. Windows 설정 → 앱 → 설치된 앱에서 ‘모두찾아줘’를 제거할 수 있습니다. 제거해도 원본 문서와 기존 검색 데이터는 보존합니다. 압축만 풀어서 사용할 경우 릴리스의 `portable.zip`을 받으면 됩니다.

## 검색

1. **폴더 추가**로 업무 폴더를 고르거나 **PC 전체 선택**을 누릅니다.
2. **색인 시작**을 눌러 문서의 목록과 내용을 등록합니다. 처음에는 시간이 걸릴 수 있습니다.
3. `관악 FP`, `SW 개발비`, `설치결과 보고서`처럼 기억나는 단어를 입력합니다.
4. 결과를 선택해 오른쪽에서 일치 내용·전체 경로·시트 목록을 확인한 뒤 **파일 열기** 또는 **폴더 열기**를 누릅니다.

여러 단어를 띄어 쓰면 **모든 단어가 포함된 문서**를 찾습니다. 단어가 파일명·경로·시트명·본문에 나뉘어 있어도 됩니다. 대소문자를 구분하지 않습니다. `"소프트웨어 개발비"`처럼 큰따옴표로 묶으면 문구 그대로 찾습니다.

문서 유형 필터, 파일명·경로만 검색, 최근 수정순 정렬과 결과 목록 CSV 저장을 제공합니다. 화면에는 최대 500개를 표시하므로 결과가 많으면 단어를 추가하세요. 파일명과 시트명에 검색어가 있으면 관련도순에서 우선 표시합니다.

단축키: `Ctrl+F` 검색창 이동, 검색창에서 `Enter` 검색, 결과 목록에서 `Enter` 파일 열기, `F5` 색인 갱신.

## 문서 변환

1. 위쪽 **문서 변환**을 누릅니다. 검색한 파일이 선택되어 있으면 바로 추가됩니다. 검색 결과의 오른쪽 클릭 메뉴로도 열 수 있습니다.
2. **파일 추가**를 누르거나 변환 창에 파일을 끌어놓습니다. 여러 파일을 한 번에 추가할 수 있습니다.
3. **출력 형식**과 **저장 위치**를 고릅니다. 모든 입력 파일에 공통으로 가능한 형식만 표시합니다.
4. **변환 시작**을 누릅니다. 각 파일의 진행 상태와 결과·오류를 표시합니다. **중지**로 취소할 수 있습니다.
5. **결과 열기** 또는 **결과 폴더**로 확인합니다. 변환된 파일을 검색 색인에 넣으려면 해당 위치를 색인 갱신하세요.

원본을 덮어쓰거나 삭제하지 않습니다. 저장 위치에 `모두찾아줘_변환_날짜_시간` 폴더를 만들고 입력 파일마다 결과 폴더를 분리합니다. 같은 이름의 입력 파일도 충돌하지 않으며, 여러 페이지와 보조 이미지 파일을 함께 보존합니다. 실패·중지한 파일의 미완성 결과는 별도 작업 폴더에서 정리하고, 이미 완료된 결과는 유지합니다.

| 입력 예 | 출력 예 |
|---|---|
| HWP·HWPX | HWP·HWPX·PDF·DOCX·TXT·Markdown·HTML·페이지 이미지 |
| DOCX·TXT·Markdown·HTML·전자책 | PDF·DOCX·HWPX·TXT·HTML·EPUB 등 |
| XLSX·XLS·CSV·TSV·ODS | XLSX·ODS·CSV·TSV·JSON·PDF·HWPX 등 |
| PPTX | PDF·페이지 이미지·DOCX·HWPX 등 |
| PDF | DOCX·TXT·HWPX·페이지 이미지·PPTX·표 데이터 XLSX 등 |
| PNG·JPG 등 이미지 | PDF와 다른 이미지 형식 |

실제 가능한 출력은 입력 형식과 설치된 엔진에 따라 화면에서 확인할 수 있습니다. PDF→PPTX는 페이지를 그림으로 만든 슬라이드이며, PDF→XLSX는 인식 가능한 표를 추출합니다. 스캔 문서의 OCR이나 문서 편집 화면은 제공하지 않습니다. 복잡한 서식·글꼴·차트는 달라질 수 있으므로 결과를 확인하세요.

**추가 엔진**에서 다음 프로그램을 선택 설치할 수 있습니다. 선택한 엔진만 Filee의 공식 고정 다운로드와 SHA-256 검증으로 받고, 문서는 외부에 보내지 않습니다.

- **LibreOffice**: 구형 DOC·PPT, OpenDocument와 일부 복잡한 문서 경로. 약 420MB 다운로드.
- **Pandoc**: 일부 문서와 마크업 형식. 약 42MB 다운로드.
- **calibre**: 일부 전자책 형식. 약 240MB 다운로드.

기본 변환 엔진은 설치 파일에 포함하므로 별도 Filee·Office·한글 설치가 필요하지 않습니다. 추가 엔진은 한 번 설치한 뒤 오프라인에서 사용할 수 있습니다. Filee의 동영상·음악·압축파일 도구, 전역 도넛 메뉴와 탐색기 확장은 이 문서 변환 창에 포함하지 않습니다.

## GitHub에서 업데이트

- 실행 시 하루에 한 번 GitHub의 최신 정식 릴리스를 확인합니다. 새 버전이 있으면 오른쪽 위에 표시합니다. 오프라인이어도 로컬 검색은 계속 사용할 수 있습니다.
- **업데이트 확인**을 누르면 언제든 최신 버전과 변경 사항을 볼 수 있습니다.
- **다운로드 후 설치**를 누르면 이 저장소의 설치 파일을 받고, 크기와 SHA-256을 확인합니다. 검증이 끝나면 진행 중인 색인을 중지·저장하고 현재 창을 닫은 뒤 업데이트 설치를 시작합니다.
- 설치가 끝나면 프로그램을 다시 엽니다. 설치 위치와 기존 색인·설정을 유지합니다. 다운로드 취소나 오류 시 현재 버전을 계속 사용할 수 있습니다.

GitHub 계정이나 Git 설치는 필요하지 않습니다. 초안·시험 버전과 현재보다 낮은 버전은 설치 대상으로 제안하지 않습니다. 릴리스에 정확한 설치 파일이나 SHA-256 정보가 없으면 설치를 진행하지 않습니다.

## 색인 갱신과 클라우드 파일

문서를 추가하거나 수정한 뒤 **색인 시작**을 누르면 바뀐 파일과 새 구조 파서가 아직 적용되지 않은 파일을 읽습니다. 첫 갱신에는 평소보다 시간이 걸릴 수 있습니다. ‘변경 자동 반영’을 선택하면 등록한 업무 폴더의 새 파일·수정 파일도 반영합니다. 중지해도 저장된 내용은 계속 검색할 수 있습니다.

OneDrive·Google Drive·MYBOX 등은 해당 폴더/드라이브가 연결되어 있고 읽을 수 있어야 합니다. **클라우드 파일 내용도 읽기**를 켜면 온라인 전용 파일을 제공자가 다운로드할 수 있습니다. 끄면 온라인 전용으로 표시된 파일은 파일명만 등록합니다. 연결 상태에 따라 파일 목록 확인이나 중지가 늦어질 수 있습니다.

PC 전체 선택은 연결된 드라이브를 대상으로 하되 Windows·프로그램·캐시·휴지통·개발 의존성·숨김 이름 폴더, 연결 지점과 임시 잠금 파일은 건너뜁니다. 접근 권한이 없는 폴더는 읽지 않습니다.

**선택 위치 제거**는 다음 색인 범위만 바꿉니다. 기존 검색 데이터는 남습니다. 없어진 파일은 **없는 파일 색인 정리**로 목록에서 제거할 수 있습니다. 연결이 끊긴 최상위 드라이브/폴더의 목록은 보존합니다. 원본 파일을 삭제하는 기능은 없습니다.

## 본문 검색 지원 형식과 제한

| 형식 | 본문 검색 범위 |
|---|---|
| XLSX·XLSM·XLTX·XLTM | 시트명과 셀 값, 수식의 저장된 계산 결과 |
| XLS·XLSB·XLT | 시트명과 셀 값, 저장된 계산 결과 |
| PDF | 텍스트가 들어 있는 PDF |
| HWP·HWPX·HWPML | kordoc로 본문·표·제목 구조 추출. 실제 쪽 정보가 있는 문서만 쪽수 제공 |
| DOCX | 본문·머리말·꼬리말·각주·미주 |
| PPTX | 슬라이드와 발표자 노트 |
| TXT·CSV·TSV·MD·LOG | UTF-8·UTF-16 또는 한국어 CP949 텍스트 |
| EML·HTML | 메일 헤더와 텍스트 MIME 본문, HTML 표시 텍스트. 메일 첨부파일 제외 |
| 구형 DOC·PPT·RTF | 파일명과 경로만 검색 |

스캔 이미지 OCR, 압축파일 내부, 암호 문서, 배포용 HWP, 삽입된 이미지·개체·도형 속 텍스트는 지원하지 않습니다. 엑셀 수식을 다시 계산하거나 매크로를 실행하지 않습니다. 미리보기는 문서 레이아웃 대신 추출한 텍스트를 표시합니다.

파일당 80MB, 본문 앞부분 약 40만 자, 압축 문서의 개별 XML 항목 30MB까지 읽습니다. 본문 읽기에 30초가 넘게 걸리면 중단하고 상태를 표시합니다. 제한을 넘거나 읽지 못한 파일도 파일명으로 검색하고, 상세 안내에서 이유를 확인할 수 있습니다.

## 데이터와 개인정보

검색 데이터와 설정은 `%LOCALAPPDATA%\FunnetDocumentFinder`에 저장합니다. 이름 변경 전과 같은 위치이므로 기존 검색 데이터를 이어서 사용합니다. 경로와 추출한 문서 내용이 포함된 로컬 SQLite 데이터베이스이며, 별도 암호화 없이 Windows 계정의 접근 권한을 따릅니다.

내 PC 문서 내용과 로컬 검색어는 외부 서버에 보내지 않습니다. 공공자료를 선택하면 질문은 해당 조회 서비스에 전달합니다. 로컬 AI는 같은 PC의 Ollama에서 처리합니다. 그 밖에 인터넷은 버전 확인·업데이트와 사용자가 선택한 추가 엔진 다운로드에 사용합니다. 원본 문서의 내용·수정일·메타데이터를 변경하지 않습니다. 클라우드 파일 읽기에 따른 다운로드와 직접 파일을 열었을 때의 동작은 해당 제공자·연결 프로그램이 처리합니다.

변환 엔진의 설정과 추가 엔진은 데이터 폴더의 `conversion-filee`에 저장합니다. 기존에 별도로 설치한 Filee의 설정을 변경하지 않습니다. Filee 및 포함된 각 라이브러리·엔진은 원본 라이선스를 유지합니다. 배포물의 `conversion/filee-2.4.1/FILEE-LICENSE.txt`와 `FILEE-THIRD-PARTY-NOTICES.md`, 저장소의 `third_party`를 참고하세요.

저장소와 배포 파일에는 개인 문서·검색 데이터베이스·인증 정보가 포함되지 않습니다. 별도 Windows 서비스나 자동 시작 작업도 등록하지 않습니다.

## 개발·릴리스

`.NET 8 SDK`로 개발합니다. 설치 프로그램 빌드에는 Inno Setup 6.3 이상 또는 7, Python 3.12 이상, Node.js 24 LTS와 npm이 필요합니다. 아이콘 재생성에는 Pillow를 사용합니다. 사용자 설치 파일에는 필요한 런타임을 포함합니다.

```powershell
dotnet run --project DocumentFinder.Tests -c Release
dotnet build DocumentFinder.App -c Release
./build-release.ps1
```

`artifacts/release`에 설치 EXE·휴대용 ZIP·`SHA256SUMS.txt`를 만듭니다. 빌드 중 `third_party/filee.json`에 고정한 공식 Filee 패키지를 받고 SHA-256을 확인한 뒤 CLI 런타임을 포함합니다. 변환 통합 검사는 자체 생성한 문서로 수행합니다. 아이콘 원본과 출처는 `assets`에 있습니다. 이용 조건은 `LICENSE.txt`, 배포에 포함되는 라이브러리 고지는 `THIRD_PARTY_NOTICES.txt`와 `licenses` 폴더를 참고하세요.

다음 버전을 배포할 때는 `Directory.Build.props`의 `Version`을 올린 후 같은 버전의 태그를 보냅니다. GitHub Actions가 검사·빌드 후 설치 파일을 GitHub Releases에 올립니다.

```powershell
# Directory.Build.props의 Version을 예: 1.2.0으로 변경한 다음
git add .
git commit -m "Release 1.2.0"
git tag v1.2.0
git push origin main --tags
```

화면 없이 색인을 갱신할 수도 있습니다. `DOCUMENT_FINDER_DATA` 환경 변수로 테스트용 데이터를 분리할 수 있습니다.

```powershell
.\ModuFind.exe --index "C:\업무" --query "관악 FP" --report "C:\업무\검색결과.json"
```

결과 JSON에는 파일 경로와 추출 내용이 포함되므로 공개 저장소에 넣지 마세요. 일반 사용은 프로그램 화면으로 하면 됩니다.
